# نظام مبايعات السيارات — النسخة الإنتاجية

نظام كامل: خادم Node.js + Express، قاعدة بيانات PostgreSQL حقيقية، تسجيل دخول بكلمة مرور (JWT)، صلاحيات لكل دور، وسجل تدقيق كامل لكل إجراء (إنشاء، اعتماد، رفض، دخول).

## الأدوار
- **مندوب مبيعات (sales_rep):** ينشئ المبايعة، ويرى مبايعاته فقط، ويعدّلها إذا رجعت مرفوضة.
- **مشرف فرع (branch_supervisor):** يعتمد أو يرفض المبايعات الجديدة.
- **مدير مبيعات (sales_manager):** يعتمد أو يرفض بعد المشرف، ويرى سجل التدقيق.
- **محاسب (accountant):** الاعتماد المالي النهائي.
- **مدير نظام (admin):** ينشئ حسابات المستخدمين ويعطّلها ويرى سجل التدقيق الكامل.

كل اعتماد أو رفض يُسجَّل باسم صاحبه وتاريخه في جدول `approvals` وفي `audit_log` — هذا هو الإثبات الداخلي البديل للتوقيع الورقي.

## النشر خطوة بخطوة على Railway (الأبسط للنشر الذاتي)

هذا أسهل مسار لأنك ما ذكرت وجود قسم IT: خدمة واحدة تستضيف الكود + قاعدة بيانات PostgreSQL مُدارة تلقائيًا.

### 1) إنشاء حساب ورفع الكود
1. أنشئ حساب مجاني على https://railway.app (تسجيل عبر GitHub أسهل).
2. ارفع مجلد هذا المشروع إلى مستودع GitHub جديد (أو استخدم زر "Deploy from GitHub repo" في Railway بعد رفعه).

### 2) إضافة قاعدة البيانات
1. داخل مشروعك في Railway اضغط **New → Database → PostgreSQL**.
2. Railway ينشئ قاعدة البيانات تلقائيًا ويعطيها متغير باسم `DATABASE_URL`.

### 3) ربط الكود بقاعدة البيانات
1. اذهب لخدمة الكود (Web Service) → تبويب **Variables**.
2. أضف نفس متغيرات ملف `.env.example`:
   - `DATABASE_URL` — اربطه بمتغير قاعدة البيانات (Railway يسمح بالإشارة إليه مباشرة من خدمة الـ Postgres).
   - `JWT_SECRET` — نص عشوائي طويل (32+ حرف)، لا تتركه كما هو في المثال.
   - `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `ADMIN_NAME` — بيانات أول حساب مدير.
   - `PORT` — اتركه فارغاً، Railway يضبطه تلقائياً.

### 4) تجهيز قاعدة البيانات وأول حساب مدير
من تبويب **Deployments → Shell** (أو من جهازك بعد ضبط `DATABASE_URL` محلياً):
```
npm install
npm run migrate   # ينشئ الجداول
npm run seed       # ينشئ حساب المدير الأول
```

### 5) التشغيل
Railway يشغّل تلقائيًا `npm start`. بعد الانتهاء يعطيك رابطًا عامًا (مثل `xxx.up.railway.app`) — هذا هو الرابط الذي يفتحه المناديب والمشرفون من أي جهاز.

### 6) أول دخول
سجّل دخول بحساب `ADMIN_USERNAME` / `ADMIN_PASSWORD`، اذهب لصفحة **المستخدمون**، وأنشئ حسابات المناديب والمشرفين والمدراء والمحاسبين من هناك (لكل واحد اسم مستخدم وكلمة مرور خاصة به).

> بديل مطابق تقريباً في الخطوات: **Render.com** (خدمة Web Service + PostgreSQL مُدار) لو حبيت تقارن الأسعار.

## ملاحظات مهمة قبل الاعتماد الكامل بديلاً عن الورق
- **النسخ الاحتياطي:** فعّل النسخ الاحتياطي التلقائي لقاعدة البيانات من لوحة Railway/Render (متوفر كإعداد جاهز).
- **القيمة القانونية للتوقيع:** الاعتماد هنا إثبات داخلي (اسم + وقت + دور) وليس بديلاً نظاميًا عن التوقيع المعتمد رسمياً؛ إذا احتجتم توقيعاً إلكترونياً معتمداً نظاماً، هذا يتطلب ربط جهة توثيق خارجية معتمدة.
- **HTTPS:** Railway/Render يوفران HTTPS تلقائياً على الروابط التي يعطونها — لا تحتاج إعداد إضافي.
- **كلمات المرور:** غيّر `JWT_SECRET` وكلمة مرور المدير فوراً بعد أول نشر، ولا تتركهما بالقيم الافتراضية.
- مع أكثر من 30 مستخدماً، الخطة المجانية غالباً تكفي للتجربة، لكن للتشغيل الفعلي اليومي يُفضّل ترقية الخطة المدفوعة (رخيصة نسبياً) لضمان الاستقرار وعدم إيقاف الخدمة بعد فترة خمول.
